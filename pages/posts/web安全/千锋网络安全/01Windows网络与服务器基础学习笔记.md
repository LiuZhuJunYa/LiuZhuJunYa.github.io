# Windows 网络与服务器基础学习笔记

> 本笔记由 12 份课程材料整理而成，按照“基础认知 → 虚拟化环境 → Windows 管理 → 权限与共享 → 网络基础服务 → 靶场实践”的顺序重组。课件中的界面来自不同版本的软件，实际菜单名称可能略有差异；其中 ESXi 6.5、Windows Server 2003 等旧版本仅适合隔离实验，不应直接用于生产环境或暴露到公网。

## 1. 学习路线与整体关系

这组内容并不是彼此孤立的知识点，而是在搭建一套完整的 Windows 网络实验环境：

1. 使用 VMware Workstation 创建和管理虚拟机。
2. 根据需要进一步搭建 ESXi/vSphere 虚拟化环境。
3. 配置 Windows 服务器的 IP、DNS、远程管理、用户和组。
4. 使用 NTFS 权限与共享权限控制文件访问。
5. 部署 DHCP、DNS、IIS、FTP 等常见基础服务。
6. 在隔离靶场中进行漏洞复现和安全验证。

| 层次     | 主要内容                                 | 解决的问题                     |
| -------- | ---------------------------------------- | ------------------------------ |
| 实验基础 | VMware Workstation、ESXi、快照、克隆     | 如何快速构建和恢复实验环境     |
| 系统管理 | Windows 安装、注册表、用户与组、远程桌面 | 如何管理主机和身份             |
| 网络配置 | IPv4、网关、DNS、工作组、域              | 主机如何通信、定位和加入组织   |
| 权限控制 | NTFS、共享权限、所有权                   | 谁可以访问哪些资源、能做什么   |
| 网络服务 | DHCP、DNS、IIS、FTP、文件服务            | 如何向客户端提供基础服务       |
| 安全实践 | 靶场、POC、EXP、日志与隔离               | 如何在授权范围内复现和分析漏洞 |

::: conclusion 学习主线
先把虚拟机、IP 地址和用户权限配置正确，再部署网络服务，最后进入靶场练习。若底层网络和权限没有理清，后续出现的“服务不可达”“认证失败”“无权访问”等问题会很难定位。
:::

## 2. 计算机与 Windows 基础

### 2.1 CPU、BIOS 与 CMOS

::: definition CPU 核心与主频
CPU 核心（Core）负责执行计算、接收与处理指令。主频是核心工作的时钟频率；在架构、核心数和其他条件相近时，主频越高通常意味着单个核心每秒可完成更多工作。
:::

::: definition BIOS 与 CMOS
BIOS 是基本输入/输出系统，负责加电自检、初始化硬件并引导操作系统。CMOS 是保存部分硬件配置和时钟信息的低功耗存储区域，通常由主板电池维持。
:::

计算机启动时可以概括为：通电 → BIOS/UEFI 自检与初始化 → 按启动顺序寻找启动设备 → 加载操作系统引导程序 → 启动操作系统。

### 2.2 Windows 版本与安装方式

课程材料列出了 Home、Professional、Enterprise、Education、Mobile、IoT Core 等 Windows 10 版本。实验环境通常优先选择专业版、企业版或 Windows Server，因为它们提供更完整的远程管理、策略和服务器角色能力。

常见安装方式：

- 从光盘或挂载的 ISO 镜像启动安装。
- 在现有系统中运行 ISO 内的 `setup.exe`，执行升级或重新安装。
- 制作可启动 U 盘，调整 BIOS/UEFI 启动顺序后安装。

::: algorithm Windows 虚拟机安装流程

1. 新建虚拟机并选择操作系统类型。
2. 挂载可信来源的 Windows ISO。
3. 分配 CPU、内存和磁盘，网络先按实验需要选择 NAT 或仅主机模式。
4. 启动虚拟机，完成磁盘分区、系统版本、账户和区域设置。
5. 安装 VMware Tools，并完成系统更新。
6. 在安装实验软件前创建“干净系统”快照。
   :::

### 2.3 注册表

::: definition Windows 注册表
注册表是 Windows 用于保存系统、硬件、用户和应用程序配置的层次化数据库。其逻辑结构由根键、子键、值名称、值类型和值数据组成，可通过 `regedit.exe` 查看和编辑。
:::

| 根键                  | 主要内容                                                    |
| --------------------- | ----------------------------------------------------------- |
| `HKEY_LOCAL_MACHINE`  | 本机硬件、操作系统和全局软件配置                            |
| `HKEY_USERS`          | 已加载的用户配置文件及默认用户配置                          |
| `HKEY_CURRENT_USER`   | 当前交互式登录用户的配置，是 `HKEY_USERS` 中对应 SID 的映射 |
| `HKEY_CURRENT_CONFIG` | 当前硬件配置文件信息                                        |
| `HKEY_CLASSES_ROOT`   | 文件关联、COM/OLE 类等信息                                  |

常见配置单元文件包括 `SAM`、`SECURITY`、`SOFTWARE`、`SYSTEM`、`DEFAULT` 和用户目录下的 `NTUSER.DAT`。

> 修改注册表前应先导出相关键或创建快照。错误修改可能导致服务异常、登录失败或系统无法启动。

### 2.4 常用系统诊断工具

- **系统信息**：查看操作系统版本、处理器、内存和计算机名。
- **任务管理器**：查看进程、性能、启动项和当前用户。
- **资源监视器**：细看 CPU、磁盘、网络与内存占用。
- **事件查看器**：排查系统、应用、安全和服务日志。
- **系统文件检查器**：检查并修复受保护的系统文件。

```powershell
sfc /scannow
```

安全模式适合卸载不兼容驱动、排查启动项、删除被占用文件或处理系统故障。可通过“系统配置”进入，也可按住 `Shift` 点击“重启”进入高级启动选项。

## 3. VMware 与虚拟化实验环境

### 3.1 虚拟机与两类架构

::: definition 虚拟机（Virtual Machine）
虚拟机是由软件模拟出的独立计算机环境，拥有虚拟 CPU、内存、磁盘、网卡等硬件，可在其中安装并运行客户操作系统和应用程序。
:::

| 架构                 | 运行方式                         | 典型场景             | 特点                         |
| -------------------- | -------------------------------- | -------------------- | ---------------------------- |
| 寄居式（Hosted）     | 虚拟化软件运行在宿主操作系统之上 | 个人学习、桌面实验   | 安装方便，但需要经过宿主系统 |
| 原生式（Bare-metal） | Hypervisor 直接运行在物理硬件上  | 数据中心、服务器集群 | 性能和集中管理能力更强       |

常见产品包括 VMware Workstation、VMware vSphere/ESXi、Microsoft Hyper-V、Oracle VirtualBox，以及 Citrix Xen 系列。容器与 WSL 也可提供隔离运行环境，但它们与完整硬件虚拟机的隔离边界和运行机制不同。

### 3.2 VMware Workstation 基本操作

::: algorithm 新建与配置虚拟机

1. 打开“新建虚拟机”向导。
2. 选择安装介质和客户操作系统类型。
3. 设置虚拟机名称与存储路径。
4. 分配虚拟磁盘容量，按实验规模配置 CPU 和内存。
5. 选择网络模式并检查虚拟网卡是否已连接。
6. 启动虚拟机并完成操作系统安装。
   :::

常用快捷键：

| 操作                               | 快捷键                |
| ---------------------------------- | --------------------- |
| 将键盘与鼠标输入切换到虚拟机       | `Ctrl + G`            |
| 释放鼠标和键盘到宿主机             | `Ctrl + Alt`          |
| 切换全屏                           | `Ctrl + Alt + Enter`  |
| 向客户机发送 `Ctrl + Alt + Delete` | `Ctrl + Alt + Insert` |

虚拟机的关机、断电和挂起含义不同：

- **正常关机**：由客户操作系统完成数据刷新和服务停止，最安全。
- **关闭电源**：类似物理机直接断电，可能造成数据或文件系统损坏。
- **挂起**：保存当前运行状态，之后可较快恢复，但仍依赖对应虚拟机文件。

### 3.3 网络模式

| 模式                | 虚拟机与宿主机 | 访问外网       | 局域网其他设备能否直接访问虚拟机 | 适用场景                   |
| ------------------- | -------------- | -------------- | -------------------------------- | -------------------------- |
| NAT                 | 可通信         | 通常可以       | 通常不直接暴露                   | 普通上网、较安全的实验环境 |
| 桥接                | 可通信         | 取决于物理网络 | 通常可以                         | 模拟真实局域网主机         |
| 仅主机（Host-only） | 可通信         | 默认不可以     | 通常不可以                       | 漏洞靶场、隔离实验         |

::: theorem 靶场网络选择原则
存在已知漏洞的旧系统、恶意样本或攻击靶机应优先使用仅主机网络；确需联网下载依赖时，可临时使用 NAT 并限制出口。不要把脆弱靶机桥接到办公网、校园网或公网。
:::

### 3.4 VMware Tools、共享文件夹、迁移、快照与克隆

- **VMware Tools**：提供增强驱动、鼠标切换、时间同步和文件交互等能力；安装后通常需要重启。
- **共享文件夹**：在 VMware 设置中启用后，可从客户机访问 `\\vmware-host\Shared Folders`。
- **迁移虚拟机**：先关机或挂起，再复制整个虚拟机目录；在目标机通过 `.vmx` 配置文件打开。
- **快照**：记录某一时刻的虚拟机状态，适合实验前后快速回滚。
- **克隆**：生成另一台虚拟机；链接克隆节省空间但依赖母盘，完整克隆独立性更强但占用更多存储。

::: theorem 快照不是备份
快照依赖原虚拟磁盘链，适合短期回滚，不应代替独立备份。重要实验结果仍应导出到独立位置，并定期合并或删除长期堆积的快照。
:::

## 4. vSphere/ESXi 环境

::: definition vSphere、ESXi 与 vCenter
VMware vSphere 是面向数据中心的虚拟化平台。ESXi 是直接安装在服务器硬件上的 Hypervisor，负责创建和运行虚拟机；vCenter Server 用于集中管理多台 ESXi 主机、资源池和集群。
:::

课程实验使用 VMware Workstation 15.5 嵌套安装 ESXi 6.5，核心步骤如下。

::: algorithm 在 Workstation 中搭建 ESXi 实验节点
1. 新建虚拟机，选择“稍后安装操作系统”。
2. 客户操作系统选择 VMware ESXi 6.x，设置名称与存储路径。
3. 配置约 60 GB 虚拟磁盘，并根据宿主机资源分配 CPU 和内存。
4. 网络选择 NAT；挂载 ESXi 安装 ISO 后启动。
5. 进入安装程序，接受许可协议，选择目标磁盘和键盘布局。
6. 设置强 `root` 密码，确认安装，完成后卸载 ISO 并重启。
7. 按 `F2` 进入系统自定义，使用 `root` 登录。
8. 在 `Configure Management Network` 中设置管理网卡、静态 IPv4、网关、DNS 和主机名。
9. 应用配置并重启管理网络，在宿主机浏览器访问 `https://<ESXi管理IP>`。
10. 登录 ESXi Host Client，检查存储、网络和主机资源，再创建虚拟机或快照。
:::

实验示例使用了类似 `192.168.200.10/24` 的静态管理地址。实际地址必须与 VMware NAT 网段一致，并避免与网关、DHCP 地址池或其他设备冲突。

> 旧版 ESXi 仅用于复现实验。生产环境应选用仍受支持的版本，使用可信镜像、合法许可、独立管理网络和严格访问控制。

## 5. 靶场环境与漏洞术语

### 5.1 常见术语

| 术语                    | 含义                                     | 重点                       |
| ----------------------- | ---------------------------------------- | -------------------------- |
| POC（Proof of Concept） | 证明漏洞确实存在的最小化描述、请求或样例 | 侧重“可验证”               |
| EXP（Exploit）          | 利用漏洞触发具体效果的代码或方法         | 侧重“可利用”               |
| 0DAY                    | 漏洞刚被发现且尚无可用修复方案的阶段     | 风险高、披露与处置要求严格 |
| CVE                     | 为公开漏洞分配的通用编号体系             | 用于跨平台检索和关联信息   |
| VUL                     | Vulnerability，泛指漏洞                  | 通用缩写                   |
| CNVD                    | 国家信息安全漏洞共享平台                 | 国内漏洞信息来源之一       |
| CNNVD                   | 国家信息安全漏洞库                       | 国内漏洞信息来源之一       |

### 5.2 课程靶场启动逻辑

材料中的示例靶机为旧版 Windows Server，并通过 phpStudy 启动 Apache/MySQL：

1. 将靶机虚拟网卡设置为 NAT 或更严格的仅主机模式。
2. 启动靶机并使用 `ipconfig` 查看 IP 地址。
3. 若系统 IIS 已占用 80 端口，先停止冲突的网站或服务。
4. 启动 phpStudy 中需要的服务。
5. 从同一实验网段的浏览器访问靶机 IP，确认靶场首页可达。

::: theorem 授权与隔离边界
漏洞验证只能针对本人所有或明确授权的系统。实验前应确认网络范围、目标 IP、允许的测试动作和数据处理方式；靶机不应保存真实业务数据，也不应与生产环境共用账号、密钥或网络。
:::

## 6. 远程管理、IPv4 与 Windows 网络组织

### 6.1 远程桌面 RDP

::: definition RDP
远程桌面协议（Remote Desktop Protocol）允许客户端实时显示并操作远程 Windows 主机。Windows 的图形客户端是“远程桌面连接”，命令为 `mstsc`，默认服务端口为 3389。
:::

::: algorithm 配置远程桌面

1. 为客户端和服务器配置可达的 IP 地址。
2. 在远程计算机上启用远程桌面。
3. 将账户加入允许远程登录的用户或组，并设置非空强密码。
4. 在防火墙中仅允许可信来源访问 RDP 规则。
5. 在客户端运行 `mstsc`，输入服务器地址和账户登录。
6. 完成管理后注销会话或断开连接，并检查事件日志。
   :::

常用参数：

```powershell
mstsc /v:192.168.10.10
mstsc /v:192.168.10.10:3389 /f
mstsc /w:1280 /h:720
mstsc /admin
```

| 参数                 | 作用                           |
| -------------------- | ------------------------------ |
| `/v:<server[:port]>` | 指定服务器及端口               |
| `/admin`             | 连接到管理会话，应谨慎使用     |
| `/f`                 | 全屏                           |
| `/w`、`/h`           | 指定窗口宽度和高度             |
| `/public`            | 以公共模式运行                 |
| `/span`              | 将桌面跨越多个显示器           |
| `/multimon`          | 使用与客户端相同的多显示器布局 |
| `/edit <file.rdp>`   | 编辑 RDP 连接文件              |

课程材料给出了通过注册表修改 RDP 端口的方法，其位置为：

```text
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\PortNumber
```

修改后还需同步调整防火墙规则并重启相关服务或主机。改变端口只能减少部分自动扫描，不能替代多因素认证、来源限制、账户锁定、网络级别身份验证和日志审计。

### 6.2 VNC

VNC 使用远程帧缓冲协议共享屏幕，通常由 VNC Server 与 VNC Viewer 组成，具有跨平台特点。RealVNC、TightVNC、UltraVNC 是常见实现。部署时要关注传输加密、认证强度、访问来源和公网暴露风险。

### 6.3 IPv4 参数

一台主机的基本 IPv4 配置包括：

- IP 地址：标识接口。
- 子网掩码：判断目标是否位于同一网段。
- 默认网关：访问其他网段时的下一跳。
- DNS 服务器：将名称解析为 IP 地址。

查看网络配置：

```powershell
ipconfig
ipconfig /all
```

使用课程中的 `netsh` 方式配置静态地址：

```powershell
netsh interface ip set address name="以太网" static 192.168.33.5 255.255.255.0 192.168.33.1
netsh interface ip set dnsserver name="以太网" static 192.168.33.1
```

恢复为 DHCP 自动获取：

```powershell
netsh interface ip set address name="以太网" dhcp
netsh interface ip set dnsserver name="以太网" dhcp
```

> 不同 Windows 版本的网卡名称可能是“以太网”“Ethernet”或自定义名称，命令中的名称必须与实际接口一致。

### 6.4 工作组与域

| 模型       | 管理方式                                   | 适用场景       |
| ---------- | ------------------------------------------ | -------------- |
| 工作组     | 主机地位相对平等，账户和策略分散管理       | 小型、临时网络 |
| Windows 域 | 通过域服务集中管理账户、计算机、策略和资源 | 组织化网络     |

修改计算机名的课程示例：

```powershell
netdom renamecomputer localhost /newname:"server01"
```

修改名称后通常需要重启。加入域前应先确认 DNS 指向域内 DNS 服务器，否则域控制器发现与认证容易失败。

## 7. 用户与组管理

::: definition 用户账户与 SID
用户账户表示一个安全主体，通常包含用户名、凭据和权限信息。Windows 使用唯一的安全标识符（SID）识别账户，因此仅看用户名不能完整判断账户身份。
:::

常见用户管理操作包括创建、重命名、重置密码、启用、禁用、删除账户，以及将账户加入适当的组。

### 7.1 内置账户

| 账户              | 用途                                     |
| ----------------- | ---------------------------------------- |
| `Administrator`   | 本地高权限管理账户，应限制使用并重点审计 |
| `Guest`           | 来宾账户，通常应保持禁用                 |
| `SYSTEM`          | Windows 核心组件使用的高权限本地系统身份 |
| `LOCAL SERVICE`   | 供本地服务使用的低权限身份               |
| `NETWORK SERVICE` | 供需要网络身份的服务使用                 |

### 7.2 组账户

::: definition 组账户
组是用户或其他安全主体的集合。把权限授予组，再通过成员关系让用户获得权限，可以显著降低逐个用户配置和审计的复杂度。
:::

需要管理员维护成员的常见内置组包括 `Administrators`、`Users`、`Guests` 和 `Power Users`。由系统动态判断成员的特殊身份包括：

- `Interactive`：当前以交互方式登录的用户。
- `Authenticated Users`：已通过身份验证的用户，通常不含匿名用户。
- `Everyone`：覆盖范围很广，授权时应谨慎。

::: theorem 以组授权，避免逐人授权
先依据岗位或项目建立组，再把用户加入组，最后把资源权限授予组。这样更符合最小权限原则，也便于人员调岗、离职和权限审计。
:::

一个实用的权限规划表应至少包含：姓名、部门、岗位、用户名、所属业务组、资源访问级别、审批人和有效期。

## 8. NTFS 权限

### 8.1 文件系统与权限类型

常见文件系统包括 FAT、NTFS 和 Linux 中常见的 EXT 系列。NTFS 支持访问控制列表、加密、压缩、配额和更完整的可靠性机制，适合 Windows 服务器权限管理。

常用 NTFS 基本权限：

| 权限           | 典型能力                                     |
| -------------- | -------------------------------------------- |
| 完全控制       | 读写、执行、删除、修改权限、取得所有权等     |
| 修改           | 读取、写入、执行和删除，但不等同于可修改 ACL |
| 读取和执行     | 读取内容并运行可执行文件                     |
| 列出文件夹目录 | 查看文件夹中的名称                           |
| 读取           | 查看文件或属性                               |
| 写入           | 创建或修改内容                               |
| 特别权限       | 对高级权限进行细粒度组合                     |

高级权限还包括遍历文件夹、读取/写入属性、创建文件、创建文件夹、删除子项、读取权限、更改权限和取得所有权等。

### 8.2 四条核心规则

::: theorem NTFS 有效权限规则

1. **累加**：用户从本人和所属组获得的允许权限通常会合并。
2. **拒绝优先**：针对同一访问请求，显式拒绝通常优先于允许。
3. **继承**：子文件夹和文件默认继承父文件夹的访问控制项。
4. **最小权限**：只授予完成工作所必需的能力和范围。
   :::

需要特别区分：

- “能读取文件”不等于“能读取权限列表”。
- “能修改文件”不等于“能更改权限”。
- 所有者通常可以调整对象的权限；管理员也可以先取得所有权，再修复权限。
- 显式权限和继承权限同时存在时，应通过“高级安全设置”检查最终访问控制项，而不是只看基本复选框。

::: algorithm 排查 NTFS 访问失败

1. 确认访问者实际使用的账户和 SID。
2. 列出该账户所属的全部组。
3. 检查目标对象及父目录的继承关系。
4. 查找显式或继承的拒绝项。
5. 检查是否只有共享权限或只有 NTFS 权限被配置。
6. 使用“有效访问”功能验证最终结果，再做最小范围调整。
   :::

## 9. 文件共享服务器

### 9.1 对等网、C/S 与文件服务器

对等网中，各主机分别管理账户、密码和资源，规模增大后维护困难。C/S 架构把资源集中放在服务器上，由客户端统一访问，便于备份、权限、配额、审计和高可用管理。

Windows 文件服务器相关能力包括：

- 共享和存储管理。
- DFS：为分布在多台服务器上的资源提供统一入口。
- 文件服务器资源管理器：设置配额、文件屏蔽和报告。

### 9.2 创建和访问共享

访问路径：

```text
\\服务器IP\共享名
\\服务器名称\共享名
```

::: algorithm 配置文件共享

1. 规划用户、组和目录结构。
2. 在 NTFS 层为业务组配置最小权限。
3. 在文件夹属性的“共享”页创建共享并配置共享权限。
4. 检查服务器本地安全策略和防火墙规则。
5. 使用不同角色的测试账户，从客户端访问 UNC 路径。
6. 分别验证读取、创建、修改和删除操作，并记录结果。
   :::

::: theorem 共享权限与 NTFS 权限取交集
用户通过网络访问共享文件时，同时受到共享权限和 NTFS 权限约束，最终权限取两者中更严格的结果。例如共享权限允许“更改”，但 NTFS 只允许“读取”，最终只能读取。
:::

影响网络访问的本地策略可能包括：

- 拒绝从网络访问这台计算机。
- 本地账户的共享和安全模型。
- 使用空白密码的本地账户只允许进行控制台登录。

### 9.3 隐藏共享与默认管理共享

共享名末尾添加 `$` 可使其不在普通浏览列表中显示，例如 `data$`。访问时仍可使用：

```text
\\server01\data$
```

Windows 还可能存在 `C$`、`D$` 等默认管理共享。隐藏不等于安全，知道准确路径且拥有权限的用户仍可访问，因此必须依靠身份认证、ACL、防火墙和审计保护。

### 9.4 文件服务器实验案例

实验目标：使用 Windows Server 集中存储公司文件，将共享目录限制为 100 MB，并阻止上传指定类型的可执行文件。

实现思路：安装文件服务/文件服务器资源管理器 → 创建用户和业务组 → 配置 NTFS 与共享权限 → 设置配额 → 设置文件屏蔽规则 → 使用不同身份验证访问结果。

## 10. IIS Web 服务

::: definition WWW 与 IIS
WWW 服务采用客户机/服务器架构，由浏览器向 Web 服务器请求页面和资源。IIS（Internet Information Services）是 Windows Server 的 Web 服务平台，也可安装 FTP 等角色服务。
:::

### 10.1 站点基本配置

部署 IIS 站点通常需要配置：

- 站点名称与物理路径。
- 绑定的 IP 地址、端口和主机名。
- 默认文档。
- 身份验证和授权规则。
- 应用程序池身份与权限。
- 连接限制、日志和防火墙规则。

### 10.2 虚拟目录与虚拟主机

::: definition 虚拟目录
虚拟目录通过别名把网站根目录之外的物理目录挂载到站点 URL 结构中，使不同模块可以分别存放、开发和维护；移动物理目录时只需调整映射，不必改变外部 URL 结构。
:::

一台服务器可通过三种方式承载多个站点：

1. 使用不同 IP 地址。
2. 使用相同 IP、不同端口。
3. 使用相同 IP 和端口、不同主机名（主机头/Host Header）。

::: algorithm 部署多个端口的 IIS 站点

1. 安装 Web Server（IIS）角色。
2. 为每个站点准备独立根目录和默认页面。
3. 分别创建站点，并为其配置不同端口。
4. 只在防火墙中开放实际使用的端口。
5. 使用 `http://服务器IP:端口/` 逐一验证。
6. 检查 IIS 访问日志和应用程序池状态。
   :::

> Web 根目录不应向普通用户授予不必要的写入或执行权限。上传目录与可执行目录应尽量分离，生产环境应启用 HTTPS，并删除默认站点、示例应用和无用模块。

## 11. DHCP 服务

::: definition DHCP
DHCP 是为客户端自动分配 TCP/IP 参数的协议，可下发 IP 地址、子网掩码、默认网关、DNS 服务器等配置。它能减少人工配置、降低输入错误和地址冲突，并提高地址利用率。
:::

### 11.1 地址分配方式

| 方式          | 含义                                     |
| ------------- | ---------------------------------------- |
| 自动分配      | 地址首次分配后长期由该客户端使用         |
| 手动分配/保留 | 管理员将特定地址绑定给指定客户端         |
| 动态分配      | 按租约临时分配，释放后可供其他客户端使用 |

### 11.2 DORA 租约流程

::: algorithm DHCP DORA 四步流程

1. **Discover**：客户端在尚无地址时广播查找 DHCP 服务器。
2. **Offer**：服务器提供可用 IP、租期和其他网络参数。
3. **Request**：客户端广播选择某个服务器及其提供的地址。
4. **ACK**：服务器确认租约，客户端应用配置；若不可用则可能返回 NAK，客户端重新开始发现过程。
   :::

客户端重启时会尝试继续使用原地址。租期达到约 50% 时，客户端通常先向原 DHCP 服务器续租；如果续租失败，会在后续阶段扩大请求范围。

### 11.3 部署与作用域规划

部署前应明确：

- DHCP 服务器使用静态 IP。
- 客户端地址池的起止范围。
- 子网掩码、网关和 DNS 地址。
- 排除范围：网关、服务器、网络设备等静态地址不得被动态分配。
- 保留地址：让特定客户端获得固定地址。
- 租期：依据客户端流动性和地址数量设置。

::: theorem DHCP 选项优先级
通常按“保留选项 > 作用域选项 > 服务器选项”的顺序应用：越具体的配置优先级越高。排查客户端获得错误网关或 DNS 时，应从最具体的保留配置向上检查。
:::

课程案例：DHCP 服务器地址为 `192.168.10.10`，作用域为 `192.168.10.100-192.168.10.200`，排除 `192.168.10.110-192.168.10.120`，并通过选项 `006 DNS Servers` 下发 DNS 地址 `192.168.10.10`。

::: algorithm DHCP 实验流程

1. 为服务器设置静态 IP，并添加 DHCP Server 角色。
2. 在域环境中使用有权限的账户授权 DHCP 服务器。
3. 新建并激活作用域，配置地址池、掩码、排除范围和租期。
4. 配置网关、DNS 等作用域或服务器选项。
5. 如有需要，为服务器或打印机创建保留。
6. 将客户端改为自动获取 IP 和 DNS。
7. 检查客户端租约、服务器地址租用记录和相关事件日志。
8. 定期备份 DHCP 数据库并验证还原流程。
   :::

## 12. DNS 服务

::: definition DNS 与 FQDN
DNS 是分布式、层次化的名称系统，用于在域名与 IP 地址等资源信息之间建立映射。FQDN 是完整限定域名，通常由主机名和 DNS 后缀组成，例如 `www.example.com`。
:::

### 12.1 名称空间、区域与服务器类型

DNS 名称空间由根域、顶级域、二级域、子域和主机名逐层构成。区域是名称空间中连续的一部分，一台 DNS 服务器可以托管多个区域。

| 类型           | 作用                         |
| -------------- | ---------------------------- |
| 主要名称服务器 | 保存区域的可写主数据         |
| 辅助名称服务器 | 通过区域传送获得只读副本     |
| 主控名称服务器 | 为其他服务器提供区域复制来源 |
| 仅缓存服务器   | 不托管权威区域，缓存查询结果 |

### 12.2 递归查询与迭代查询

::: algorithm 典型 DNS 解析过程

1. 客户端向配置的本地 DNS 服务器发起递归查询。
2. 本地 DNS 先检查缓存和本地区域。
3. 未命中时，本地 DNS 通过根提示或转发器继续查询。
4. 采用迭代查询时，上级服务器返回更接近目标区域的服务器地址。
5. 本地 DNS 最终向目标权威服务器取得记录。
6. 将结果缓存并返回客户端。
   :::

- **递归查询**：请求方期待最终成功结果或失败结果。
- **迭代查询**：服务器无法直接回答时，可返回下一步应查询的服务器。
- **正向查询**：域名 → IP。
- **反向查询**：IP → 域名。

### 12.3 常见资源记录

| 记录  | 用途                                   |
| ----- | -------------------------------------- |
| SOA   | 描述区域起始授权信息和主要服务器等参数 |
| NS    | 指定区域的权威名称服务器               |
| A     | 将主机名映射到 IPv4 地址               |
| PTR   | 将 IP 地址映射回 FQDN，用于反向查询    |
| MX    | 指定邮件交换服务器                     |
| SRV   | 定位提供特定服务的服务器               |
| CNAME | 为规范名称建立别名                     |

### 12.4 子域、委派、区域传送与转发

| 机制       | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| 子域       | 记录仍保存在父区域文件中，由父区域权威服务器管理           |
| 委派       | 子域拥有独立区域和权威服务器，父区域只保留指向它的委派信息 |
| 区域传送   | 将区域数据从主要服务器复制到辅助服务器，用于冗余和分担查询 |
| 转发器     | 把本地无法解析的查询转给指定 DNS 服务器                    |
| 条件转发器 | 仅将特定域名的查询转发到指定服务器                         |
| 根提示     | 提供根 DNS 服务器位置；若同时配置，通常优先使用转发器      |

::: algorithm DNS 服务器部署流程

1. 为服务器配置固定 IP。
2. 安装并启动 DNS Server 角色。
3. 创建正向查找区域，必要时创建反向查找区域。
4. 添加 A、CNAME、PTR 等资源记录。
5. 配置转发器或确认根提示可用。
6. 将客户端 DNS 指向该服务器。
7. 分别测试内部记录、公网域名、正向查询和反向查询。
8. 检查缓存、事件日志、区域复制和防火墙规则。
   :::

### 12.5 DNS 安全关注点

- **区域传送泄露**：仅允许指定辅助服务器执行区域传送。
- **缓存投毒/欺骗**：及时更新服务端，限制递归范围并使用合理的转发策略。
- **DNS 劫持**：保护客户端 DNS 配置、路由器和管理账户。
- **拒绝服务**：限制不必要的公网递归，实施监控和速率控制。
- **错误委派或记录污染**：对区域变更进行审批、备份和审计。

## 13. FTP 服务

::: definition FTP
FTP 是基于客户机/服务器架构的应用层文件传输协议，为用户提供上传、下载和目录操作能力。Windows Server 可通过 IIS 的 FTP Publishing Service 提供 FTP 服务，也可使用 Serv-U、FileZilla Server 等软件。
:::

常见客户端包括命令行 `ftp`、专用图形客户端以及部分旧式浏览器。现代浏览器通常不再把 FTP 作为通用访问方式，实验时更适合使用专用客户端。

### 13.1 基本访问

```text
ftp 192.168.10.40
```

登录后常见命令：

| 命令            | 作用          |
| --------------- | ------------- |
| `dir` 或 `ls`   | 显示目录      |
| `cd`            | 切换远程目录  |
| `get`           | 下载文件      |
| `put`           | 上传文件      |
| `mget` / `mput` | 批量下载/上传 |
| `bye`           | 退出          |

### 13.2 IIS FTP 部署

::: algorithm 搭建 IIS FTP 站点

1. 添加 IIS 的 FTP Server/FTP Service 角色服务。
2. 准备 FTP 根目录并规划用户或组。
3. 新建 FTP 站点，设置绑定地址、端口和 TLS 选项。
4. 配置身份验证与授权规则。
5. 为根目录设置匹配的 NTFS 权限。
6. 在防火墙中开放控制端口和所需的被动端口范围。
7. 使用不同权限账户验证上传、下载、覆盖和删除行为。
   :::

### 13.3 Serv-U 与课程案例

Serv-U 的基本配置包括：创建域、指定监听 IP/端口、设置密码策略、创建用户、设置根目录、访问权限和磁盘配额。

课程包含两个案例：

1. 将 FTP 根目录与 Web 站点根目录关联，让网页设计人员上传网站文件，并按角色配置权限。
2. 为每名员工分配 1 GB FTP 存储空间，分别设置用户目录、访问权限和配额。

::: theorem FTP 安全原则
传统 FTP 的认证和数据传输可能是明文的，不适合在不可信网络中传输敏感数据。优先使用 SFTP 或正确配置的 FTPS；不要为方便实验直接关闭整台服务器的防火墙，应只开放所需端口和可信来源。
:::

## 15. 综合实验建议

可以把各章内容串成一套小型企业网络实验：

::: algorithm 综合实验：搭建一套 Windows 服务网络

1. 在 VMware 中创建一台 Windows Server 和两台客户端，网络使用仅主机或独立 NAT 网段。
2. 为服务器设置静态 IP，记录网段、网关和 DNS 规划。
3. 创建部门用户与组，按岗位建立权限矩阵。
4. 部署 DHCP，配置地址池、排除范围、网关和 DNS 选项。
5. 部署 DNS，建立内部区域和服务器 A 记录，并配置转发器。
6. 创建文件共享，组合共享权限与 NTFS 权限，验证不同角色的有效权限。
7. 部署 IIS 多站点，分别测试不同端口和主机名绑定。
8. 如需文件发布，配置受限 FTP/FTPS 账户和独立上传目录。
9. 仅对管理主机开放 RDP，检查登录与服务日志。
10. 每完成一个稳定阶段创建快照，并记录配置、验证结果和故障处理过程。
    :::

### 15.1 故障排查顺序

遇到“访问不了”时，建议按以下顺序检查：

1. **主机状态**：虚拟机是否启动，服务是否运行。
2. **链路与网段**：网卡是否连接，双方是否在预期网段。
3. **IP 配置**：IP、掩码、网关是否正确，是否地址冲突。
4. **名称解析**：直接访问 IP 是否正常，DNS 查询是否正确。
5. **端口监听**：服务是否监听预期 IP 和端口。
6. **防火墙与路由**：规则是否允许正确协议、端口和来源。
7. **身份认证**：使用了哪个账户，密码和登录权限是否满足。
8. **资源授权**：共享权限、NTFS 权限和应用层授权是否同时满足。
9. **日志**：检查事件查看器、IIS/FTP/DNS/DHCP 日志和安全日志。

::: conclusion 最终总结
这套课程的核心不是记住每个界面的点击位置，而是建立一条稳定的判断链：**先确认虚拟化与网络连通，再确认身份与权限，最后确认服务配置和安全边界**。在安全实验中，快照、隔离、最小权限、精确开放防火墙和完整日志同等重要。
:::
