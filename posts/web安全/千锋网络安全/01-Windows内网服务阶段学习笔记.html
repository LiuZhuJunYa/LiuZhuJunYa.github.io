1.2 计算机启动、操作系统和注册表 ​

CPU 执行指令，内存保存运行中的数据，磁盘提供持久存储。虚拟机中的这些部件由虚拟化平台呈现给客户操作系统，分配资源时仍然受物理主机容量限制。

课件使用 BIOS 说明启动过程。学习时记住“固件初始化与自检 → 选择启动设备 → 加载引导程序 → 启动操作系统”即可；采用 UEFI 的设备在具体实现和界面上会有所区别。为实验安装系统，应先确认目标是虚拟磁盘，避免误把物理机分区当成安装对象。

注册表是 Windows 保存系统、用户和软件配置信息的层次结构数据库。项类似目录，值包含名称、类型和数据；“配置单元”则是一组能够装载、保存的注册表数据。

常见根键理解重点
HKEY_LOCAL_MACHINE，简称 HKLM本机硬件、系统和软件配置
HKEY_CURRENT_USER，简称 HKCU当前用户配置，关联 HKEY_USERS 中对应用户的配置
HKEY_USERS，简称 HKU已加载的用户配置
HKEY_CLASSES_ROOT，简称 HKCR文件关联、COM 等信息；是 HKLM\Software\Classes 与 HKCU\Software\Classes 的合并视图
HKEY_CURRENT_CONFIG，简称 HKCC当前硬件配置相关信息的视图

课件第 21 张把 HKCR 简化为 HKCU 子树，学习时应以上表中的合并视图关系理解。Microsoft：HKEY_CLASSES_ROOT 的合并视图 初学时先练习查询和导出，编辑前记录原值与修改目的。注册表导出不等同于完整系统备份，也不适合代替完整的恢复方案。

powershell
# 查看操作系统基本信息，不修改配置
Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, OSArchitecture

# 查询 Windows 版本相关注册表值
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object ProductName, DisplayVersion, CurrentBuild

任务管理器用于观察进程与资源占用；资源监视器帮助定位磁盘、网络等活动；事件查看器用于追踪系统和应用记录。发生系统异常时，先记录时间、错误内容、近期变更，再检查相关日志。安全模式只加载有限的驱动和服务，适合定位驱动或软件冲突；进入安全模式本身不能证明恶意程序已被清除。

1.3 网站访问的基本链条 ​

Internet 是网络互联的基础设施；Web 是运行在其上的一种服务。浏览器是客户端，Web 服务程序和业务程序运行在服务端。域名方便记忆，IP 地址用于网络寻址，端口帮助把流量交给相应服务。

text
输入 URL
  → 浏览器检查相关缓存并进行名称解析
  → 建立与服务器的传输连接
  → 使用 HTTPS 时完成 TLS 协商与证书验证
  → 发送 HTTP 请求
  → Web 服务器或应用处理请求，必要时访问数据库
  → 返回 HTTP 响应
  → 浏览器解析内容，并继续请求图片、脚本等资源

以实验地址 http://web.lab.example.test:8080/index.html 为例：http 是协议，web.lab.example.test 是主机名，8080 是显式指定的端口，/index.html 是路径。DNS 解析出 IP 不代表该端口已经开放；端口能连通也不代表应用返回正确内容。

请求中常见的方法、路径、请求头和请求体分别回答“做什么、操作哪个资源、附带什么元信息、提交什么数据”。响应中的状态码、响应头和响应体说明服务器的处理结果。学习时至少区分：200 表示请求成功处理，301/302 常用于重定向，403 表示拒绝访问，404 表示资源未找到，500 表示服务端处理出错。状态码是线索，仍需结合应用的具体行为判断。

WAMP 表示 Windows、Apache、MySQL、PHP 的组合；LAMP 中的 L 表示 Linux。IIS 是另一种 Web 服务器。它们不是必须同时启动的组件：若两个程序尝试监听同一 IP 和端口，就可能发生冲突。

1.4 入门术语与靶场的作用 ​

术语学习时的准确理解
POC用于证明某种问题成立的样例、描述或程序，不一定包含完整利用链
EXP利用某个漏洞完成特定动作的方法或程序
Payload在某次输入或利用中承载目标行为的数据、代码或命令，不限于“拿到权限以后执行”
Fuzzing向程序提供大量变异、异常或边界输入并观察行为，可结合黑盒、灰盒或白盒方法
Webshell借助 Web 运行环境提供命令或文件操作能力的脚本；文件后缀本身不能决定其性质
CVE用于标识已公开漏洞记录的编号体系，编号本身不等于风险等级
CTF围绕安全题目或攻防场景开展的竞赛，竞赛规则不等于真实项目授权

靶场提供可恢复、可控制的练习对象。在这里，重点是观察“正常配置是什么、改变某个条件后发生什么、如何验证和恢复”。课内旧系统和带漏洞组件保留在隔离实验网，不作为日常办公、存放个人资料或对外提供服务的系统。

2.2 一次主机检查如何形成闭环 ​

方法：从检查需求走到整改复测

  1. 确认需求与范围。 明确目标清单、检查时间、测试账户、允许使用的方法及联系人。
  2. 确定检查依据。 使用项目指定的基线、管理要求和经过确认的适用文件；原课堂笔记中的标准编号存在不完整写法，不据此推定正式标准。
  3. 访谈与收集信息。 了解业务用途、运维方式、备份恢复要求、已有防护和近期变更。
  4. 逐项核查并留证。 记录对象、时间、配置值、工具版本与必要截图，避免将口令、密钥或无关业务数据带入报告。
  5. 分析风险并提出措施。 说明触发条件、可能影响和业务约束，给出具体可验证的整改建议。
  6. 实施经确认的整改。 安排变更窗口、备份或回退手段，并记录修改内容。
  7. 复测与交付。 验证原问题是否解决、是否影响业务，保留“已修复、部分修复、待处理或风险接受”等明确状态。

原资料强调报告、整改记录和复测，这比记住某款检查工具更有价值。课内提到的工具加白和外接介质接入，需要结合现场既有管理流程；不能为了方便检查而随意停用防护或接入未知设备。

3.1 理解虚拟机与虚拟化平台 ​

虚拟机是获得虚拟 CPU、内存、磁盘、网卡等资源的独立运行环境。宿主机承载虚拟化平台，客户机是在虚拟机中运行的操作系统。

架构理解方法课内例子
寄居型先有宿主操作系统，再运行虚拟化软件VMware Workstation
裸机型虚拟化层直接管理硬件资源ESXi

vSphere 是虚拟化平台体系；ESXi 负责运行虚拟机；vCenter Server 提供多主机的集中管理。把 ESXi 安装到 Workstation 的虚拟机里属于嵌套虚拟化，适合理解结构，性能和兼容性仍受宿主硬件与配置限制。

课件演示了 Workstation 12/15 和 ESXi 6.5 等历史环境。本笔记保留其操作逻辑，不把这些版本当作新部署选型依据，也不要求为跟随课程而重装物理机系统或关闭系统防护。

网卡模式连接特点本阶段用途
仅主机模式默认形成宿主机与虚拟机使用的内部虚拟网本地服务与旧靶机实验
NAT通过宿主侧的网络地址转换访问外部网络经确认需要更新或下载的实验环境
桥接虚拟机接入物理网络，可能被同网设备访问仅在明确需要并已规划时使用

仅主机网络的隔离还取决于宿主路由、共享和转发设置；双网卡虚拟机也可能把两个网络连在一起。旧靶机保持在内部实验网，避免额外挂接桥接网卡。进行课程 DHCP 实验时，关闭该实验虚拟网自带的 DHCP 服务，否则客户端可能从错误的服务器获得地址。

3.3 新建、导入和验证虚拟机 ​

首次搭建可按以下顺序进行：

  1. 查看物理机可用内存、磁盘空间和硬件虚拟化状态，为宿主系统保留足够资源。
  2. 新建虚拟机，选择与镜像匹配的客户系统、固件类型及虚拟硬件兼容级别。
  3. 选择独立的虚拟机目录，配置适量 CPU、内存与虚拟磁盘，挂载可信来源的系统镜像。
  4. 安装系统并设置独立的实验管理员口令，完成所需驱动和 VMware Tools 配置。
  5. 连接到规划好的实验虚拟网，配置地址和主机名，记录初始状态。
  6. 正常关机后创建基础快照，再开展服务配置练习。

识别常见文件时应纠正现有随堂笔记中的混淆：.vmx 是虚拟机配置文件，.vmdk 是虚拟磁盘相关文件，不能把 .vmx 当成快照可执行程序。迁移时应保留完整虚拟机文件集合，尤其不要遗漏快照依赖的磁盘链。

“我移动了它”和“我复制了它”主要影响虚拟机标识等信息的保留或重新生成，并非由“是否跨电脑”决定。保留同一台虚拟机身份与创建一个新副本是两种不同目的。克隆后的系统还应检查主机名、IP、应用配置和操作系统部署要求，避免地址冲突。

3.4 快照、克隆和备份各自解决什么问题 ​

手段适合场景需要记住的限制
快照实验前保存状态，配置出错后回退通常依赖原磁盘，不能代替独立备份
完整克隆快速生成相对独立的实验副本占用更多存储，副本仍需检查身份和地址
链接克隆节省空间地创建多个练习节点依赖父虚拟机或基础快照，移动删除父文件会影响子机
备份应对磁盘损坏、误删或整套环境丢失需要独立副本，并验证恢复过程

课内强调关机做快照。初学实验采用正常关机后的快照便于控制状态；产品也可能支持运行时快照，是否包含内存、能否保证应用一致性需要另行确认。给多节点域环境回退时，还要考虑节点之间的状态关系，不能把单机回退理解为整套分布式环境自动恢复一致。

3.5 靶场启动的最小验证 ​

导入现成靶机后，先检查网络模式和 IP，再查看目标服务是否启动。PHPStudy 等集成环境只是管理服务的工具，界面显示“已启动”后仍要通过浏览器验证实际页面。

powershell

    Where-Object LocalPort -in 80, 443, 8080 |
    Select-Object LocalAddress, LocalPort, OwningProcess

# 在实验客户端测试指定端口

4.1 四个网络参数要分清 ​

参数作用实验例子
IP 地址标识接口使用的网络地址192.168.56.20
子网掩码或前缀长度判断哪些目的地址属于本地网段255.255.255.0 或 /24
默认网关向非本地网段发送流量时使用的下一跳纯隔离实验可留空
DNS 服务器处理域名等名称解析请求DNS 实验中为 192.168.56.10

地址相近不一定处于同一网段，必须结合掩码判断。同网段主机间通信通常不需要经过默认网关；跨网段则需要适当的路由。课件把“两台主机设为同网段”作为入门条件，这是简化实验的方法，远程桌面并非只能在同一网段使用。

powershell
ipconfig /all
route print
ping 192.168.56.20
Test-NetConnection 192.168.56.20 -Port 3389

ping 主要检查 ICMP 回应，可能被策略禁用；它失败不能直接证明主机离线，它成功也不能证明 RDP 或 Web 服务正常。有效的排查顺序是网卡与地址、路由、目标端口、认证和应用。

4.2 远程桌面如何工作 ​

RDP 用于远程图形桌面操作，默认端口为 3389，涉及 TCP，也可使用 UDP 改善体验。客户端可运行：

powershell
mstsc /v:192.168.56.20

要连通，需要目标系统支持相应的远程桌面主机功能、服务已开启、网络路径与防火墙允许访问，登录账户同时满足组成员关系和相应的登录策略。仅知道口令或仅加入某个组，并不保证可以登录。

实验时在目标虚拟机控制台开启远程桌面，为专用实验账户授予所需权限，只允许实验网中的管理来源访问。保留控制台入口，以便配置失误后修复。连接后区分“断开”与“注销”：断开可能保留会话和其中运行的程序，注销则结束该用户会话。

课件提到更改端口和 mstsc /admin。更改端口会增加运维配置，不应替代身份验证、访问限制和日志审计；/admin 用于管理会话，不能理解为绕过权限或必然强行替换任意用户。VNC 是另一类远程屏幕控制方案，其认证和传输保护取决于具体产品配置，不能因为能显示远程桌面就假定连接已加密。

4.3 身份用 SID 标识，权限常通过组分配 ​

用户名便于人识别，SID 是 Windows 安全机制用于标识账户等安全主体的标识符。账户重命名通常保留原 SID；删除后重新建立同名账户，则不能假定它仍是原来的身份。

本地账户由本机管理，域账户由域集中管理。登录与访问资源时需要明确使用的是 计算机名\用户、域名\用户 还是用户主体名称，避免把同名的本地账户和域账户混为一谈。

身份或组认识重点
Administrator内置管理员账户；日常工作使用可追责的个人账户并控制提权
Guest来宾身份，不为解决访问故障而随意启用
Administrators本机管理员组，成员资格需要严格控制
Users普通用户组，不等于“没有任何权限”
SYSTEM操作系统和服务使用的高权限本地身份
LOCAL SERVICE、NETWORK SERVICE服务身份，具有不同的本地权限与网络访问行为
Authenticated Users、Everyone特殊安全主体；范围较广，授权时须结合实际身份与策略判断

推荐通过“用户 → 业务组 → 资源权限”建立关系。例如，把编辑人员加入 LabEditors，给组配置实验目录的修改权限；岗位调整时主要变更成员关系，避免逐个文件维护个人权限。

powershell
whoami
whoami /user
whoami /groups
net user
net localgroup

五、NTFS 权限与文件共享 ​

对应课程资料：1.5 Windows 权限相关/1.5.1 NTFS安全权限/NTFS安全权限.pdf 第 4—17 页；1.5.2 文件共享服务器/文件共享服务器.pdf 第 4—13、16 页。

5.1 先分清“允许登录”和“允许操作文件” ​

身份认证回答“你是谁”，资源授权回答“你可以做什么”。账户能登录，不代表可以读取所有目录；能列出文件名，也不等于能读取文件内容、修改数据或删除文件。

NTFS 用访问控制列表表达主体与权限的关系。常见基本权限包括读取、读取和执行、写入、修改、完全控制；高级权限进一步细分读取数据、创建文件、删除、更改权限、取得所有权等动作。

权限主要能力易混淆处
读取查看数据及相关信息不等于可修改
写入创建或写入内容等不天然等于可删除所有现有文件
修改读取、写入、执行及删除等通常不包括任意更改 ACL
完全控制包含修改权限、取得所有权等管理能力业务编辑人员通常不需要

删除行为还可能受到父文件夹“删除子文件夹及文件”等权限影响，不能只检查文件本身的一条“删除”勾选项。

5.2 权限如何累加、继承和拒绝 ​

允许权限通常可以从用户和多个组累加。例如，用户通过一个组获得读取，通过另一个组获得写入，在没有其他限制时可能同时具备这两类能力。父文件夹上的可继承条目则可能传播给子文件夹和文件，是否生效还取决于适用范围和继承设置。

课件将规则简写为“拒绝优于允许”。这适合作为某些基础例子的提醒，但不能扩大为所有 ACL 情形下的绝对规则。规范排序的 DACL 中，显式条目在继承条目前；显式条目内部拒绝在允许前；继承条目按父级到更远祖先的顺序处理，并在相应层次先拒绝后允许。访问检查会按条目顺序处理请求的权限，因此需同时考虑条目来源、排序、适用范围及请求的具体权限。Microsoft：DACL 中 ACE 的顺序

实际操作以“高级安全设置 → 有效访问”以及真实测试账户的访问结果交叉验证。不要给 Everyone 添加大范围拒绝来修补复杂授权；这可能同时影响本来应该正常使用资源的人。

Get-Acl 'C:\LabShare' | Format-List

5.3 共享权限和 NTFS 权限是两道关口 ​

SMB 共享允许通过 \\服务器\共享名 访问文件资源。直接在服务器本地访问目录时，主要检查 NTFS 等本地访问控制；通过网络共享访问时，还要经过共享权限检查，并受身份、登录权和相关策略影响。

在分别算清两侧有效权限之后，可以把最终的网络访问能力理解为两侧都允许的操作，即交集。

共享层面NTFS 层面网络访问时的结果
读取修改只能读取
更改读取只能读取
更改修改可执行双方共同允许的读写和删除等操作
完全控制修改不因此获得 NTFS 权限管理能力

在共享名末尾加 $ 可减少普通共享列表中的显示，但知道名称的人仍可请求访问；隐藏共享不是访问控制。C$ 等默认管理共享也必须依靠真实权限和管理策略保护。

6.1 站点、绑定、目录和进程身份 ​

一个 Web 站点需要确定物理目录和访问入口。IIS 的绑定把协议、IP 地址、端口及主机名等信息联系起来。多个站点可以通过不同 IP、不同端口，或相同 IP 与端口下的不同主机名进行区分。使用域名分站点时，DNS 负责找到服务器，HTTP 请求中的主机名再参与站点选择；单纯新增 DNS 记录不会自动建立 IIS 站点。

虚拟目录用 URL 中的别名映射其他物理目录；Web 应用还涉及独立的应用边界和运行配置。应用程序池提供进程隔离等能力，其身份需要读取站点文件，而写入能力只赋予确有需要的目录。不要为解决访问错误直接给整个站点目录授予宽泛完全控制。

7.1 DORA 解释首次租约过程 ​

DHCP 可以向客户端提供 IP、掩码、网关、DNS 等参数。服务器通常配置固定地址，并根据作用域管理可分配的地址和租期。DHCPv4 的常见端口是服务器 UDP 67、客户端 UDP 68。

text
客户端                         DHCP 服务器
  | ---- Discover：寻找服务器 ----> |
  | <--- Offer：提出地址等配置 ---- |
  | ---- Request：请求所选配置 ---> |
  | <--- ACK：确认租约 ----------- |

这四步称为 DORA。它是典型首次获取过程，不代表每次续租都重复四步，也不能把所有报文无条件记成广播。

客户端通常在租期约 50% 时进入续租阶段，先尝试向原服务器请求续租；若未成功，到约 87.5% 时进入重新绑定阶段，尝试寻找可用服务器。具体计时可由协议参数指定。T1 续租没有成功，并不意味着立即失去仍在有效期内的地址；租约到期仍未续租成功时，不能继续把过期地址当作有效配置使用。RFC 2131，第 4.4.5 节

7.2 作用域、排除、保留与选项 ​

配置项作用
作用域对应子网的可管理地址范围、掩码和租期等
排除范围不从动态池分配的地址，适合保留给静态配置节点
保留根据客户端标识等信息，为指定客户端分配固定地址；客户端仍使用 DHCP
选项提供 DNS、路由器、DNS 后缀等额外参数

Windows 域环境中的 DHCP 授权帮助管理域内合法服务器，但它不是网络中所有设备都会遵守的认证屏障，不能由此认定接入网络的任意第三方 DHCP 都被阻止。服务器、作用域、保留等层次存在配置覆盖关系，检查时应核对客户端最终获得的值。多台 DHCP 可以通过协调的地址规划或故障转移提供冗余；导致问题的是未协调的重叠地址池、错误参数等配置，不能仅因发现两台服务器就断定存在冲突。

八、DNS：从记住 IP 到理解名称服务 ​

对应课程资料：1.6 Windows 服务相关/1.6.3 Windows下的DNS服务角色/Windows下的DNS服务角色.pdf 第 4—13、15—22、25—26 页。

8.1 域名、区域和权威服务器 ​

DNS 是分布式、层次化的名称系统。域名空间表达名称层次，区域则是管理与权威数据的边界；一个区域不一定包含其所有子域，子域被委派出去后可以由其他权威服务器负责。

主机全名如 web.lab.example.test。本笔记采用 .test 下的实验名称，DNS 数据在自己的实验服务器上维护，不依赖注册公网域名。

记录主要用途需要区分的含义
A名称到 IPv4 地址不包含应用端口
AAAA名称到 IPv6 地址不能用 A 记录替代
CNAME别名指向另一个名称目标是名称，不能直接填写 IP
PTR反向查询记录不因新增 A 记录就必然自动存在
MX指定邮件交换目标及优先级不是任意 Web 服务的寻址方式
NS指定区域的权威名称服务器与递归服务器角色可以区分
SOA区域管理信息，如序列号及复制相关计时不应只理解为“一个服务器地址”
SRV指明某类服务所在主机、端口等AD 服务定位的重要基础

传统主辅区域与 AD 集成区域要分开理解：

区域类型数据怎样维护排错重点
标准主要区域维护可写的主副本确认修改的是实际权威数据，不是另一个同名独立区域
标准辅助区域从指定服务器通过区域传送获得只读副本检查传送许可、来源与序列号，不能直接把副本当主副本编辑
AD 集成区域将区域数据存入 AD，通过 AD 复制，可由承载该区的可写 DC/DNS 更新检查复制范围、目录复制及动态更新权限，不能套用唯一可写主服务器的模型

客户端的“首选/备用 DNS”是查询目标设置，与服务器上的“主要/辅助区域”不是同一个概念；DNS 子域或委派也不会自动建立 AD 子域。

8.2 递归、迭代、转发与缓存 ​

客户端通常向配置的递归解析器请求结果；解析器可以从缓存或本地权威数据回答，也可以向上游查询。典型解析器向根、顶级域和相应权威服务器查询时使用迭代过程，从转介中逐步找到答案。若配置转发器，本地解析器通常把查询交给上游递归服务器处理，不能把“服务器之间的查询”一律称为迭代。

正向与反向描述的是查询内容方向，递归与迭代描述的是查询处理方式，它们不是同一组分类。DNS 常使用 UDP 53，也需要支持 TCP 53 处理相应场景，不能只放行 UDP 就认为服务完整。

缓存能减少重复查询，但也会造成修改后暂时看到旧结果；TTL 表示记录可缓存的时间。NXDOMAIN 等否定结果也可能被缓存。排错时要知道正在查询哪一台 DNS、查询哪种记录，而不是反复刷新浏览器。

子域可以继续放在父区域中管理；委派则把相应子域的权威职责交给另一个区域及服务器。区域传送用于维护副本，需要限制到预期的复制伙伴，避免向无关对象暴露成批内部记录。

九、FTP：文件传输中的控制连接与数据连接 ​

对应课程资料：1.6 Windows 服务相关/1.6.4 Windows下的FTP服务角色/Windows下的FTP服务角色.pdf 第 4—13、16—18 页。

9.1 FTP 为什么能登录却列不出目录 ​

FTP 使用控制连接交换命令，另外建立数据连接传输目录列表和文件。常见控制端口是 TCP 21；控制通道连接成功，只能证明命令连接建立，不能证明数据通道也畅通。

模式数据连接由谁发起排错重点
主动模式服务器连接客户端提供的数据端点客户端侧入站策略、地址和 NAT；传统主动模式常使用服务器 TCP 20 作为数据源端口
被动模式客户端连接服务器告知的数据端点服务端被动端口范围、对外公布地址、NAT 与防火墙映射

因此，“FTP 数据永远只走 20 端口”是错误记法。IIS 的被动 FTP 可以配置数据通道端口范围，并与防火墙、外部地址配置保持一致。Microsoft：IIS FTP 防火墙设置

传统 FTP 的凭据和内容可能明文传输；FTPS 是在 FTP 上使用 TLS，SFTP 则基于 SSH，不能把三者当作同一种协议的不同名字。客户端也需要明确选择服务器实际提供的协议。

9.2 认证、授权和 NTFS 权限需要同时满足 ​

IIS 可以安装 FTP 相关角色服务，Serv-U 等软件也能提供文件传输服务。建立站点时，需明确绑定、物理根目录、认证方式、授权规则和数据通道设置。某用户通过登录认证，并不等于自动获得目录读写能力；服务授权和底层文件权限仍然会限制操作。

课件为了演示简化环境，出现“关闭防火墙”和通过浏览器访问 FTP 的做法。复现实验应按所用客户端和服务配置实际需要的规则，使用支持相应协议的专用客户端，不把关防火墙当成标准步骤。匿名访问也不是默认必需功能。

十、Windows 日志：把操作变成可追溯的证据（1.7） ​

10.1 日志在哪里，能回答什么问题 ​

课件《Windows日志》第 3—5 页给出的主线是：确定主机，采集样本，分析事件，保存证据，形成处置闭环。初学时应先掌握事件查看器 eventvwr.msc，再使用命令筛选；筛选工具不能补回从未记录的事件。

日志通道常见内容主要用途
Application应用自身记录的错误、警告和运行事件判断服务异常、应用崩溃与故障时间
System服务控制、驱动、系统组件事件判断服务安装、启动失败和系统状态变化
Security登录、账户管理、进程创建等安全审计关联账号、主机、行为和时间
应用程序和服务日志DNS、任务计划、远程桌面、PowerShell 等组件的专用日志补充某个服务的行为细节

前三类日志通常位于 %SystemRoot%\System32\winevt\Logs\ 下，对应 Application.evtx、System.evtx、Security.evtx。应保留原始 EVTX，截图只适合辅助说明。读取安全日志或导出日志通常需要相应权限。

审核策略、日志容量和保留方式要提前配置。 开启“审核对象访问”后，还需要给目标对象设置相应的 SACL，才能记录预期的文件访问；开启进程创建审核，并不等于事件里自动包含命令行。

10.2 事件 ID 必须与通道、提供者一起看 ​

下面是用于复习的常见事件，不代表它们一定存在于每台机器。除特别注明者外，提供者为 Microsoft-Windows-Security-Auditing，通道为 Security；是否产生取决于相应审核子类别、操作是否发生及日志是否保留。事件 ID 的官方索引可查 Microsoft 的监测事件表。

事件 ID含义分析时要补看的信息
4624登录成功目标账号、登录类型、来源地址、登录 ID；网络访问成功也可能产生，不能一概理解为远程桌面登录
4625登录失败失败原因、目标账号、来源地址、频率；输错密码或旧服务凭据也会造成失败
4672新登录被分配特殊权限与同一次登录的账号、登录 ID 关联；系统与管理员的正常活动也会产生
4688新进程创建父进程、程序路径、运行身份；需启用进程创建审核
4720用户账户被创建创建者、被创建账号、发生在哪台机器；结合变更记录确认用途
4732成员加入启用安全的本地组目标组、成员 SID、操作者；重点核实是否进入高权限组
4740用户账户被锁定调用方计算机、锁定时间；检查旧密码服务或反复登录失败
1102安全审核日志被清除Security 通道，提供者为 Microsoft-Windows-Eventlog；核实操作者和维护记录
7045系统中安装了服务System 通道，提供者为 Service Control Manager；核实服务路径、账号和安装时间

4688 中的命令行还需要单独启用“在进程创建事件中包括命令行”，且命令行可能包含敏感参数，采集与保存要限制访问。见 4688 官方说明。1102 的提供者与其他大多数安全审核事件不同，见 1102 官方说明。7045 的来源与含义可对照 Microsoft 的系统事件示例。

课件第 8 页把远程桌面事件放在一起介绍，实际检索时要区分：1149 常见于 TerminalServices-RemoteConnectionManager/Operational；21、24、25 常见于 TerminalServices-LocalSessionManager/Operational。认证成功、会话登录成功、断开、重连是不同环节，不能只看到“成功”便认定已经完成一次交互登录。

10.3 实验：重建一次自己的登录过程 ​

前提： 在隔离实验机上启用相关登录审核，使用自己的普通测试账号，记录实验开始时间与时区。只进行一次主动输错和一次正确登录，避免触发账号锁定。

十一、任务计划与备份：验证自动执行和恢复能力（1.8） ​

11.1 备份类型与恢复目标 ​

《Windows任务计划与备份》第 4—16 页介绍备份、Windows Server Backup、wbadmin 和恢复操作，第 17—22 页介绍任务计划与实验。课件混用了多个 Windows Server 版本，界面名称和支持的备份目标需按实验系统核对，不应照搬成跨版本限制。

方式保存什么恢复到最近一次备份通常需要什么
完整备份本次选定范围内的完整数据对应的一份完整备份
增量备份相对上次备份后的变化最近完整备份及之后所需的增量链
差异备份相对最近完整备份后的变化最近完整备份和所选差异备份

差异备份属于帮助区分概念的学习补充。若教材通过“档案位”解释传统文件备份：完整与增量通常清除档案位，差异不清除；不能把这个机制泛化到所有现代块级、去重或合成备份产品。

还要区分两个业务问题：RPO 是最多能接受丢失多久的数据；RTO 是发生中断后希望多久恢复业务。例如每天一次备份的系统，并不能仅凭“有备份”就宣称满足小时级的数据恢复需求。

虚拟机快照有利于实验回退，但通常依赖原始虚拟磁盘与同一存储，不能代替独立备份。数据副本要考虑异地或离线保存、访问控制与可恢复性；把备份一直挂在原主机可写的位置，仍可能遭到误删或恶意破坏。

十二、Windows 域与 AD：集中管理身份、资源和策略（1.9） ​

12.1 先分清域、目录、域控制器 ​

《Windows域环境基础-1》第 4—13 页介绍基础概念，-2 介绍部署，-3 介绍对象和组策略，-4 介绍信任与排错。

域、AD DS 和域控制器

域是用于组织身份与资源管理的逻辑范围；**AD DS（Active Directory Domain Services）**提供目录和域服务，保存用户、组、计算机等对象及属性；**域控制器（DC）**是承载 AD DS 并提供相关服务的服务器。三者分别描述管理范围、服务体系和服务器角色。

概念作用不要混淆的地方
工作组各计算机分别管理本地身份和权限同名本地账号不因此自动成为同一个身份
域集中管理域身份、成员计算机及策略不是把机器放进相同 IP 网段
OU（组织单位）在域内组织对象、委派管理并链接 GPOOU 不是安全组，不能靠加入 OU 获得文件权限
安全组按成员关系分配访问权限组不是 GPO 的直接链接位置
域树具有连续 DNS 名称空间的域集合例如父域和其子域；不等于一棵 OU 树
林共享相关目录基础的一个或多个域树一棵域树也能组成一个林
站点根据网络连通性组织子网与 DC主要服务于定位和复制，不等同于部门 OU

域名相似不等于存在 AD 信任；信任也不等于已经授权访问文件。 信任帮助使用来自另一受信任域的身份，最终能否访问资源仍需检查相应权限。课件 -4 第 2 页将子域写得过宽，应理解为现有域 DNS 名称空间下的下级域；新增另一棵域树的根域不能笼统叫子域。

域常用于划分身份管理与域数据复制范围，林是更重要的 AD 安全隔离边界；同林的不同域不能视为抵御林内高权限管理员的严格安全隔离。可对照 Microsoft 对域与林边界的定义。域/林功能级别描述可用目录功能及兼容条件，不是成员计算机的系统版本。AD LDS 是面向应用的轻型目录服务，不等同于完整的域控制器。

12.2 实验：建立单域并加入客户端 ​

以下在前文隔离网络中进行：DC01 为 192.168.56.10/24，WEB01 为 .20，CLIENT01 为 .30，无默认网关，域名为 lab.example.test。需要支持角色安装的 Windows Server 和支持加入 AD 域的客户端版本。机器名称必须唯一。

  1. 在 DC01 设置静态地址，安装 AD DS 角色；按服务器管理器的部署流程，将服务器提升为新林的域控制器，并配置 DNS。

12.4 GPO：先看对象与作用范围，再看优先级 ​

组策略对象 GPO 可链接到站点、域和 OU。计算机配置跟随计算机对象，用户配置跟随用户对象；把用户放进正确 OU，不代表同 OU 名称下的计算机配置就会对该用户生效。

通常按 LSDOU 处理：本地 → 站点 → 域 → 从父到子的 OU。同一容器有多个链接时，链接顺序数字 1 的优先级最高，通常最后处理。无冲突设置可共同生效；遇到冲突还要考虑强制链接、阻止继承、安全筛选、WMI 筛选和环回处理等条件。不能简单记成“下级永远覆盖上级”。参见 组策略处理官方说明。

实验： 在“实验用户”OU 创建并链接一个限制更改桌面背景的测试 GPO；把测试用户放入 OU，使用该用户重新登录 CLIENT01，然后检查策略结果。

预期： 目标用户应用了预期 GPO，其他测试用户不受影响。部分设置需要注销或重启才能完成，gpupdate 返回成功并不说明所有设置都已达到期望状态。

策略未生效时，先检查用户还是计算机设置、对象所在 OU、GPO 链接和筛选，再查看 gpresult 与事件日志。不要把“退域再加域”作为第一步。域用户的密码策略也不是通过任意 OU 的 GPO 自由分开设置，需要区分域账号策略与细粒度密码策略。

课件还介绍了 MSI 软件分发：先准备受控的软件共享位置，再按用户或计算机配置策略；分配与发布的强制程度、适用对象不同。客户端所用身份必须能读取安装包，不能为方便分发开放无关发现服务或扩大共享写权限。

十三、PKI 与 HTTPS：验证服务身份和保护传输（1.10） ​

13.1 公钥、私钥、证书各做什么 ​

《PKI技术与应用》第 4—11 页介绍 PKI，第 13—16 页介绍证书服务，第 19—21 页给出 Web 站点 HTTPS 实验。

概念作用需要记住的边界
对称加密通信双方使用共享密钥保护数据适合批量数据加密，密钥分发需要安全机制
非对称密码使用一对相关的公钥和私钥加密方案与签名方案有各自的算法和用途
数字签名私钥签名，公钥验证签名用于验证来源与完整性，本身不负责隐藏正文
数字证书将身份与公钥绑定，并由颁发者签名证书通常可公开分发，服务器私钥需要保密
CA审核并签发、管理和撤销证书客户端仍需建立对 CA 的信任
RA协助核验申请者身份与申请资料是否独立设置取决于 PKI 部署

课件用“私钥加密摘要”帮助解释签名，但这不是适用于所有签名算法的通用定义。更准确的记法是：签名者使用私钥执行签名算法，验证者使用对应公钥验证。不能把私钥签名理解为任何人都无法阅读的信息加密。

证书通常包含主体、颁发者、公钥、有效期、序列号、签名与扩展。对 HTTPS 而言，还应关注 **SAN（使用者可选名称）**中的 DNS 名称、服务器身份验证用途以及证书链。TLS 服务名称验证应使用 SAN 中对应的名称标识，不能只填写 CN 就假定客户端会认可；参见 RFC 9525 的名称验证规则。

HTTPS 是 HTTP 在 TLS 保护下传输。课件使用“SSL”这一传统称呼，学习时不要因此启用已经淘汰的 SSL 协议。HTTPS 保护传输，并不修复 SQL 注入、越权等应用漏洞，也不表示网站内容本身一定可信。

13.2 实验：为已有 IIS 站点配置 HTTPS ​

前提： WEB01 的 HTTP 服务已经能通过 http://web.lab.example.test:8080 访问，DNS 把该名称解析到 192.168.56.20。在隔离域中准备实验 CA；把 CA 与 DC 合并仅为节省实验资源，不能直接作为生产架构方案。

  1. 在 WEB01 生成证书申请，明确请求的 DNS 名称为 web.lab.example.test，并在申请或模板中正确包含 SAN。
  2. 由实验 CA 按选定模板审核并签发证书；将证书安装回生成对应私钥的服务器。
  3. 在 IIS 为原站点添加 HTTPS 绑定，选择 TCP 443 和正确证书；多站点共享端口时根据需要配置主机名与 SNI。
  4. 向实验客户端部署实验根 CA 信任，在 WEB01 的防火墙按实验客户端范围放行 HTTPS。
  5. 使用 https://web.lab.example.test 访问，检查页面、证书名称、有效期与信任链。证书申请成功不等于服务器已完成 HTTPS 绑定。

预期： 客户端访问名称与 SAN 匹配，证书链受信任且处于有效期内，页面正常返回。仅能建立 TCP 连接，不能证明 TLS 认证已经成功：

powershell
Test-NetConnection web.lab.example.test -Port 443

排错： 名称错误时检查访问 URL 与 SAN；信任错误时检查根与中间证书；有效期错误时检查系统时间；无法握手时检查绑定、私钥可用性、协议兼容与防火墙。用 IP 访问仅含域名的证书也可能报名称不匹配，不应通过长期忽略警告来“解决”。

导出 .cer 等证书文件通常只包含公开证书；导出包含私钥的 .pfx 需要额外保护和访问控制。不能把私钥、PFX 密码或完整证书服务备份放进公开博客。

16.4 对课堂简化说法补齐条件 ​

视频中的演示帮助认识入口，部分口头经验需要带着条件理解：

  • 账户与服务只是线索。 入侵不一定创建新账户，服务描述也可以被修改；没有陌生账户或自动服务，不能据此排除事件。
  • 任务计划不必然以 SYSTEM 运行。 应查看实际任务主体；创建任务本身不会自动让低权限账户获得更高权限。
  • 端口号不决定恶意程度。 应结合监听程序、连接方向和业务用途判断，外联多也可能是正常服务行为。
  • hosts 中的差异需要解释。 同一服务可能使用 CDN 或不同节点，单次解析得到的地址不一致不能直接判为篡改；127.0.0.1 等本地映射也可能来自合法屏蔽或测试配置。应结合已批准配置、变更和可信解析结果核对。
  • 情报未命中不表示安全。 新出现的恶意地址可能尚未被记录；命中标签也要核查时间和上下文。视频中的历史示例不作为当前恶意指标。
  • 先考虑证据与业务影响，再做清理。 视频有立即删除账户、终止进程等口头做法。现场应根据持续损害决定隔离与止损，保留必要证据并记录操作；不把大范围删除、修改注册表或重启当成默认第一步。

讲师在结尾再次强调，学习的是能反复使用的思路和手册，并衔接下一节检查报告交付。可把自己的练习结果整理成“现象 → 假设 → 查询 → 证据 → 判断 → 处置与验证”的记录；没有观察或验证过的部分，保留为待确认项。

十九、阶段复习题与参考答案 ​

先遮住答案，尝试用自己的实验环境解释。能说出“如何验证”，才算从记忆走向掌握。

题目参考答案
1. 为什么 ping 通服务器仍打不开网站？ping 主要验证相应 ICMP 通信；还需检查 TCP 端口、服务监听、站点绑定、名称解析、应用状态和防火墙。
2. 桥接、NAT、仅主机分别要关注什么？桥接可能直接进入现实局域网；NAT 通常经宿主出口访问外部；仅主机适合隔离实验，但仍需确认宿主路由、共享与虚拟网络配置。
3. 为什么快照不能代替独立备份？快照通常依赖原盘与原存储，原存储损坏时可能一起丢失；备份还需验证独立保存和恢复。
4. 用户加入管理员组后一定立即获得所有权限吗？不一定；组成员变化可能需要重新登录更新访问令牌，还受 UAC、具体权限、策略与对象访问规则影响。
5. 为什么共享设为读取，NTFS 设为修改，远程仍不能写？通过共享访问需要同时通过共享与 NTFS 权限，两层约束共同作用；还需检查实际登录身份和组成员。
6. “拒绝永远优先”能完整描述 NTFS 吗？不能。要考虑 ACE 的显式/继承、顺序与所请求权限；在典型规范顺序下同层拒绝优先，不能忽略显式允许与继承拒绝的关系。
7. DHCP 获取地址为什么会冲突？可能存在多个 DHCP、未排除的静态地址或错误作用域；应核对租约来源、虚拟 DHCP 和地址规划。
8. DNS 解析成功说明什么，没说明什么？说明查询获得了相应记录；未证明目标服务可达、身份可信或应用正常。
9. FTP 能登录却不能列目录，先查什么？控制连接正常不等于数据连接正常；检查主动/被动模式、数据端口、地址发布、NAT 和防火墙，再查目录权限。
10. 4625 数量增加就能断言暴力破解吗？不能；可能是输错、过期凭据或服务配置问题，应结合来源、频率、账号分布和后续成功事件判断。
11. 开启进程创建审核后，为什么 4688 没命令行？命令行记录是额外策略，需要单独配置，并注意敏感参数暴露。
12. 仅添加 hosts 或 DNS A 记录能加入 AD 域吗？不能；还需要域控定位、网络、时间、支持的客户端、身份权限以及正常域服务。
13. OU 和安全组分别解决什么问题？OU 用于目录组织、管理委派及 GPO 范围；安全组按成员关系分配资源权限。
14. GPO 为什么没有按“下级覆盖上级”生效？还可能有强制链接、阻止继承、筛选、链接顺序、环回与用户/计算机范围差异，应检查结果策略。
15. HTTPS 成功访问后还需要检查应用漏洞吗？需要。TLS 保护传输与服务身份验证，越权、注入等应用问题仍需单独检查。
16. 执行策略限制变化会不会自动提权？不会；它影响脚本启动条件，不改变账号本身的权限。
17. 计划任务显示成功为什么仍不能验收？还需核对真实产物、运行身份、输出内容和触发条件，返回码不等于业务目标完成。
18. 应急时为什么不应先删可疑文件再调查？可能破坏证据和关联信息，也可能误伤业务；应先记录、核实并按影响选择隔离和处置。
19. 工具检查出“不符合”能直接标为漏洞吗？不能；需确认适用基线、角色、实际配置和影响，排除误报后再形成风险结论。
20. 一份检查报告最核心的闭环是什么？明确范围 → 可复核证据 → 有依据的风险判断 → 可执行整改 → 复测结果及遗留事项。
21. 综合录屏 00:26 的“Everyone/完全控制”说明所有人都能修改文件吗？不能。该窗口在“审核”选项卡，属于 SACL；实际访问还要核对 DACL，产生日志还需要相应审核策略。
22. FTP 登录框出现后可以写“文件传输验证成功”吗？还不能；需要实际检查认证结果、目录列表与传输结果，控制连接和数据连接也要分别核对。
23. 应急课是否要求每次从账户开始按十项固定顺序检查？讲师在 00:13:00 明确说明没有固定顺序；已有篡改时间等线索时，应优先沿相关日志和证据调查。
24. 任务计划是否天然以 SYSTEM 运行并获得高权限？应检查任务实际主体、权限与配置，创建任务本身不会自动提权。
25. 综合录屏出现蓝屏后，能否直接断定是 AD 角色引发？画面只支持记录停止代码与时间，根因需要进一步证据，不能凭相邻操作推断因果。
